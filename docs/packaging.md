# 原生 noFF 打包与验收

## 唯一发布路径

当前只交付 Windows x64 的 StreamCap.exe。它内嵌前端和默认配置，不内嵌 Python、Node、FFmpeg、用户设置、账号或录制文件。运行依赖系统 WebView2 和 Microsoft Visual C++ v14 x64 运行库；常规录制需要独立的 FFmpeg，原生 FLV 直下除外。

所有命令从 desktop 目录执行。工具安装步骤见仓库 README。首次构建先用 cargo fetch --locked 为前端、core 和 src-tauri 三个 manifest 准备依赖；正式构建使用锁文件和离线模式。

```powershell
npm run verify
```

统一验收脚本执行 Rust 格式/Clippy/测试、依赖审计、WASM 构建、UI 与布局回归、原生 EXE 的关闭和托盘 smoke，并写入新的测试证据目录。任一必要检查失败会返回非零，不发布成功报告。

```powershell
pwsh -NoProfile -File .\scripts\build-release.ps1
```

仅构建时，脚本先调用同一个 build-frontend.ps1，再构建 Rust shell。直接运行 npm run tauri:build 也会通过 Tauri 的 beforeBuildCommand 重建前端。三个入口不依赖旧 dist。

输出目录为 desktop/src-tauri/target/native-noFF-时间戳/。已有 StreamCap.exe 不会被覆盖。交付文件是 StreamCap.exe 与 StreamCap.exe.sha256，不是安装器。

## 工具和依赖

- Rust 1.95.0、wasm32-unknown-unknown、MSVC C++ 工具与 Windows SDK。
- Node.js 24/npm 用于 Tauri API、锁定版本的 mpegts.js 本地资源和 Playwright；不会随 EXE 启动 Node。
- FFmpeg 与同目录 ffprobe 用于生成隔离媒体夹具和校验转封装；noFF 成品不捆绑这两个工具。
- Trunk 0.21.14、wasm-bindgen-cli 0.2.129 安装在 desktop/target/tools。升级 wasm-bindgen 库时必须同步项目本地 CLI，构建时会检查版本。
- cargo-audit 0.22.2 同样安装在 desktop/target/tools。首次审计联网更新 desktop/target/advisory-db，三份锁文件使用同一数据库版本；npm audit 也需要网络。审计 JSON 和数据库提交号保留在验收目录，已知漏洞阻断验收，维护状态警告单独保留，不自动忽略漏洞。
- Playwright 浏览器默认使用 desktop/build/playwright，可通过进程级 PLAYWRIGHT_BROWSERS_PATH 明确指定。安装浏览器时使用相同路径；验收会先启动并关闭一次无页面的隔离 Chromium，缺少浏览器会明确失败。
- Tauri 命令权限自动文件由 build.rs 生成，不手动维护；手写权限在 src-tauri/permissions/desktop.toml。

## 验收隔离

native-smoke.ps1 只接受项目 src-tauri/target 内的构建产物，使用新建的数据目录、随机 API/CDP 端口和自己的 WebView2 profile，不启动已部署的程序。源码测试使用模拟平台，本流程不重新扫码或访问真实直播间。

媒体门禁生成合成 H.264/AAC TS，检查增量预览、手动停止、自然结束、分段和退出后的转换；ffprobe 与解码校验必须通过。原生窗口必须实际播放录中的 TS 和生成的 MP4，关闭后播放器/连接/子进程不得残留。取消、损坏输入、同名输出及文件保护均有回归，不以“播放器容器显示正常”替代实际播放。

验证产物写入 desktop/tests/artifacts。保留 result.json、日志及最终截图；不能把用户目录当成测试临时目录。回收站测试仅使用新建夹具，回收失败验证必须确认原文件仍存在。

## 用户数据保护

默认用户目录为 %APPDATA%\StreamCap，下载路径由用户配置决定。--data-dir 可以显式指定独立数据目录；--api-port 可以指定本地端口，前端地址由原生启动配置注入。

不得整目录打包根 config、用户 profile、下载目录或旧备份。编译仅内嵌 config/default_settings.json；语言与版本使用原生界面数据，不再播种旧版语言/版本元数据。已有用户目录中的这些文件仍保留，任务与 Cookie 的持久化契约不变。不要清空系统 WebView2 数据，也不要因发布 noFF 而移除用户已有 FFmpeg。

向现有安装位置替换 EXE、提交 Git 或推送不属于构建脚本行为。

## 回归验证范围

- 扩展平台通过注入式 HTTP 响应夹具逐分支验证；测试从不发送真实平台或登录请求。夹具覆盖不代表外站当前可用性证明。
- 全录制格式分别验证普通与分段文件；同时覆盖 TS 清理、失败保留、锁定源文件、队列重启恢复、时间字幕、FLV 原生直下及兼容/直播源预览。
- UI 测试运行真正的发布 WASM，模拟账号/工具/关机端点，验证账号读写期间的草稿与凭据保护、更新链接、截图、删源后切换播放器、语言切换、快捷键和页面恢复。真实通知、关机及用户脚本不在自动验收中执行。
- Windows 脚本进程树门禁仅启动合成的 pwsh 睡眠进程，校验关闭 Job Object 后父子进程均退出，不执行用户脚本。
- 原生关闭/托盘 smoke 使用新数据目录。noFF 只保留一条 Rust 后端路径，不启动 Python 或 Node。
- 设置竞态回归覆盖乱序读取、串行外观保存和未保存草稿；列表负载回归在 100、250、500 个任务中更新五路进度，校验单轮一秒预算和卡片身份不变。
- 录后脚本回归覆盖同名再次录制、转换失败、关闭转换和分段部分成功；脚本只接收当前录制对应的文件。
- 退役入口检查同时禁止旧字体、旧 macOS 图标、旧截图和静态语言/版本文件重新进入仓库；保留品牌 SVG 母版及现用运行资源、许可证。

需要指定候选输出目录时，运行 `scripts/verify-native.ps1 -OutputDirectory <绝对目录>`。目录必须位于 desktop/src-tauri/target 内，且不能覆盖已有候选 EXE。

CI 统一使用 .github/workflows/test.yml，支持 push、PR 和 workflow_dispatch。各入口执行同一验收脚本并上传证据；只有手动运行且验收成功时上传 noFF EXE，不额外保留第二条构建工作流。

按时间预览门禁使用超过 600 MiB 的合成红/蓝 TS，直接跳到后段再跳回前段，并解码首帧核对画面。原生窗口用鼠标拖动录中进度条、返回最新位置，并确认录制未停止；只更新界面数字不能视为通过。

## 完整优化后的验证与运行边界

- 平台 HTTP 连接池按域名、代理、Cookie、超时与重定向策略隔离，最多 32 个会话、空闲 5 分钟过期；扫码登录不进入共享会话池。原生 TLS 明确启用 ALPN，仍允许服务端选择 HTTP/1.1。
- 解析、FLV 直下使用应用显式代理；FFmpeg/ffprobe 不继承代理环境变量。关闭应用代理不等于绕过系统 TUN，最终出站节点必须由系统代理路由证据确认。
- FLV 直下最多跟随 5 次重定向，拒绝循环、HTTPS 降级、含用户信息的目标与明显的公网到本机跳转；跨源跳转不发送原始 Cookie、Authorization 或自定义凭据头。
- 媒体库列表只读当前层文件元数据，目录体积通过独立请求异步计算。后台文件操作最多 4 项并行，界面最多同时请求 2 个目录体积；切页取消旧请求。体积缓存最多 64 项、30 秒有效，未知值不显示为零。
- 文件预览先探测编码；不兼容 MP4 转入现有有界片段预览，而非另起一套播放器。原生播放解码失败只允许一次兼容切换，解码错误不会被自动播放提示覆盖。
- 后处理保留全部待处理任务，阶段进度来自 FFmpeg 的媒体时间；探测阶段没有可计算百分比时明确显示未知。显示的是本阶段预计剩余时间，不冒充整个队列的完成时间。删源前的验证不减弱。
- 原生日志每份约 4 MiB，当前文件加 4 份历史文件，启动不清空；轮转只处理固定日志文件名，拒绝链接。新增日志写入对明显凭据字段脱敏。
- Tauri 更新到 2.12.0；依赖审计继续保留所有告警，另记录 Windows 目标依赖可达性，不使用 ignore 关闭告警。上游无替代版本的维护警告不声称已修复。

### 显式真实验收

自动化默认仍只使用隔离夹具。真实测试需显式传入项目内候选 EXE、只读用户配置目录、只读录像目录和项目内 mpv 对照程序：

~~~powershell
pwsh -NoProfile -File .\scripts\verify-real.ps1 -Executable <项目内候选EXE绝对路径> -ProfileDirectory <用户配置根目录> -MediaRoot <真实录像根目录> -MpvPath <项目内mpv.exe绝对路径>
~~~

真实平台最多抽样 7 个已开启监控的任务，沿用平台限流，遇到验证码、登录或风控即停止该平台后续抽样。已有 Cookie 只读并在内存中使用，不写入日志或测试配置；不扫码、不操作验证码、不启动用户任务。真实源预览最多读取 15 秒或 512 KiB；存在可用 FLV 时，再通过随机本地端口进行最多两次源请求、每次最多约 4 MiB 的受控断流恢复测试，仅写隔离输出。记录传输、业务可读性、目标房间和媒体可用性；未开播不能等同于已验证直播恢复。

真实录像脚本只接受项目 target 下的 SHA256 匹配候选包，用随机 API/CDP 端口及全新 profile；连接 WebView2 前检查监听进程归属，播放前后核对原录像 SHA256 和目录清单。mpv 对照使用 CPU 解码和空视频输出，不是 libmpv 嵌入或 GPU 显示性能证明，不随产品分发。

传入 -ProxyConfig <本机代理配置路径> 可只读观察 sing-box 控制接口，仅保留本次测试进程的目标域名与出站规则，控制凭据不输出、不复制。

也可向 verify-native.ps1 传入 -IncludeReal 以及上述三个真实路径参数，将真实验收纳入总门禁。真实测试存在外部阻塞或缺项时生成独立报告并返回非零；核心自动化通过不替代真实场景通过。日志、截图、样本及候选产物保留，缓存和中转文件仅按明确清单清理。


## 2026-09-27 验证与交付约定

- 本地状态使用 SSE 持久连接；5 秒心跳、20 秒失联检测、重连后全量同步。广播溢出先丢弃旧积压再请求同步，不把旧事件覆盖到新快照。HTTP/WS 的选择不改变直播平台自身的开播发现能力；自动检测继续遵守用户间隔和平台退避，网页刷新不触发平台探测。
- `400002` 保留官方页面检查路径，不等同于 HTTP 429。实际可见滑块优先于频繁文案；真实限流继续暂停自动请求。冷却、登录提示、页面不可读状态保留“检查页面”，异常页面显示后不自动销毁、不自动刷新，验证码由用户操作。
- 快手页面使用应用自己的账号隔离持久 profile，不读取 Edge profile；同账号刷新 Cookie 不更换 profile。换账号不复用旧账号存储。人工打开受独立的 30 秒预算及单窗口限制，不能清除 HTTP 冷却。成功结果仍核对房间、任务版本和保存的身份，暂停任务不会自动开录。
- 完成文件的兼容预览由同一 FFmpeg 进程连续输出，不再每 120 秒拆播放器；前端暂停读取施加背压，约 30 秒前向缓存、30–60 秒后向回收，单个网络块/解码队列可能带来超量。原录像只读，不生成全片代理。录中预览仍以已探测的文件快照为界，抵达已录尾部再请求新数据。冷跳需重新定位/解码，不承诺任意格式零延迟。
- `verify-native.ps1 -ArtifactsDirectory <项目 tests/artifacts 内不存在的绝对目录> -OutputDirectory <项目 src-tauri/target 内目录>` 可指定可复核的验证与候选目录。`verify-real.ps1` 同样支持 `-ArtifactsDirectory`；真实服务不可用与离线回归分开报告。
- 根目录 `StreamCap.exe`、`StreamCap.exe.sha256` 是候选交付，不自动替换安装版，且不进入 Git。日志、截图、报告及候选保留；仅确认清单中的临时目录移入 `de`，由用户手动清理。

- 更换直播间后，已开启监控的任务保存成功即排入一次受平台限流约束的检测；恢复监控同样立即排队。普通改名不额外探测，暂停、定时窗口和仅通知模式仍有效。正常周期仍使用用户的检测间隔；4500 秒就是 75 分钟，不等于开播推送，未开播检测不能靠 SSE/WS 自动加速。
- 录制与媒体库预览共用一个应用级播放面板。最小化后以非模态小窗继续播放，切换设置或任务页面不重建播放器；恢复保留位置、暂停及音量状态，关闭才释放预览资源，不停止后台录制。原生 MP4 起始时间非零时定位到首个实际缓冲时间，不通过放宽超时或生成完整代理规避。

## 2026-09-28 运行优化

- 任务预览按任务 ID 同步最新名称与直播状态。删除任务会关闭其预览、取消文件请求；普通状态更新保留正在播放的实例。媒体库独立文件预览不受其他任务删除影响。
- 平台请求先排队再占执行槽位：新增、恢复与手动检测优先，最多连续 3 次优先准入；普通任务等待 30 秒后提升机会，仍保留平台间轮转、并发上限、最小请求间隔和冷却。每个平台最多 1024 个等待项，取消会释放排队位置，不自动关闭用户监控。
- 外部通知采用最多 128 个待发及发送中消息、4 个发送工作任务的内存队列。同任务串行发送，连续重复状态合并，开播/下播转换顺序保留；满额明确报错。队列不跨重启持久化，应用退出会取消发送并清空待发消息。
- 媒体库支持名称、修改时间、大小及升降序，在当前桌面 profile 记忆排序。目录始终优先，未知体积排在同类已知项之后，异步体积更新不阻塞页面。
- 快手新增单目标只读核验，明确区分网络可达、业务可读和目标身份。存在播放地址不构成开播证明；没有真实冲突证据时保留原判定，不自动覆盖 Cookie。
